## 4. Mali ioctl 分发表（本机 ABI）

| cmd | handler | 结构 |
|---|---|---|
| 0xc0188404 | pp_and_gp_start_job_wrapper | 24B {ctx:u64, *gp(104B), *pp(408B)} ← **真实流量走这个** |
| 0xc1988400 | pp_start_job_wrapper | 408B 单发 PP |
| 0xc0688500 | gp_start_job_wrapper | 104B 单发 GP |
| 0xc0288302 | mem_bind_wrapper | 40B {ctx, vaddr, size, flags, ..., phys} |
| 0xc0108303 | mem_unbind_wrapper | 需内部句柄，绕开 |
| 0xc0288300 | mem_alloc | |
| 0xc020830a | mem_write_safe | cookie 写（纹理上传通道） |
| 0xc0688202 | wait_notif | 104B 完成等待 |
| 0x80108307 / 0xc0388208 | MMU 页表 query/dump | GPU 挂起时读寄存器失败，不可用 |

## 5. GPU 地址布局（回放用）

| GPU VA | 内容 | 来源 |
|---|---|---|
| 0x10000000 +0x40000 | 窗口1：命令流/tile list/varyings（varyings @ +0x2b280） | 抓包 win1.bin |
| 0x10040000 +0x4000 | 窗口2：纹理（64×64 RGBA8 平铺序） | 抓包 win2.bin |
| 0x40000000 (EXT_VA) | carveout 测试页（写校准/WB0 输出） | 自分配 |
| 0x40002000 (WB_VA) | 目标写窗口（与校准分离，防重复绑定 panic） | 自分配 |

PP job 关键字段（408B uargs）：0x08 user_job_ptr｜0x14 frame_registers｜0xa8 WB0 组（**0xac = WB0 目标物理地址**）｜0x170 cookies（置 0）｜0x190 通知指针。fence 字段必须清零（防 timeline panic）。

## 6. u-boot 环境

`env_backup.img`（标准 u-boot env：CRC32 + key=value）。关键变量：
- `bootcmd=run storeboot`、`bootdelay=1`、`aml_dt=txl_mt_cvte`
- `cmdline_keys`：追加 serialno/mac 到 ${bootargs}
- **bootargs 不在 env 也不在 DTB**——由 u-boot 运行时构造 → env 方案改 cmdline 不可行（这也是选内核补丁的原因）。
- boot.img 的 second 段是 Amlogic `AML_` 多 DTB 包装（5 个 DTB，槽位 2048/53248/104448/157696/208896，页对齐）。

## 7. 构建环境

- NDK r21e（clang --target=armv7a-linux-androideabi23 / aarch64-linux-android23，-static）
- Python 3：pyelftools、capstone、fdt
- adb：platform-tools（本包 tools/adb/）
- 编译环境变量坑：TEMP/TMP 必须指向可写目录（坑 #B1）
