# 06 回滚与恢复

## 1. 当前已做的修改清单（全部可回滚）

| 修改 | 位置 | 回滚方法 |
|---|---|---|
| 内核补丁 sel_write_enforce（7 字节） | boot 分区 (mmcblk0p14) | `dd images/boot_backup.img of=/dev/block/boot` |
| /system/xbin/su（setuid su） | system 分区 | `rm /system/xbin/su`（走 root_cmd 通道） |
| /system/bin/rootify.sh | system 分区 | `rm /system/bin/rootify.sh` |
| install-recovery.sh 末尾追加一行 | system 分区 | 恢复 `/data/local/tmp/install-recovery.sh.orig`（原厂已备份） |
| sys_call_table[246..259]、core_pattern、selinux_enforcing | 内核态（RAM） | 重启即清零；或 kfunc 写回 ni 地址 |
| roothelper.sh / root_cmd.sh / su 等 | /data/local/tmp | rm 即可，无系统影响 |

## 2. 分区镜像备份（PC 侧，本包 images/）

| 文件 | 内容 | 校验 |
|---|---|---|
| boot_backup.img | 原厂 boot（20971621B，含 101B 尾部冗余） | ANDROID! 头，gzip 内核可完整解压 |
| boot_patched.img | 当前已刷入的补丁版（8939520B） | 与原厂 Image diff = 7 字节 |
| env_backup.img | 原厂 u-boot env（8MB） | CRC + key=value 可读 |
| kernel_Image_patched.bin | 补丁内核明文（16422416B） | 与原厂仅 7 字节差 |
| system_backup.img | /system 分区完整 1GB 镜像 | **应恰好 1073741824 字节**（见 §4） |

## 3. 各种故障场景

### 3.1 电视黑屏/启动异常（怀疑 boot 补丁）
1. adb 若仍可用（大概率可用——adb 不依赖 boot 里的修改）：直接 dd 回原厂 boot。
2. adb 不可用：进入 stock recovery（未动过）尝试；最终手段是 eMMC 离线刷写（需拆机 + USB Burning Tool + 对应型号镜像，**本机没有公开 OTA 包，这是最后底线**）。

### 3.2 /system 改坏了（删错文件）
从 `system_backup.img` 提取原文件 push 回去（方法见 05 文档 §4）。

### 3.3 root 状态丢失（重启后 su 失效）
按 `02-复刻手册.md` §5 的 5.2~5.4 重跑写入链（30 秒），再触发 coredump 修复。前提是 getenforce 为 Permissive（内核补丁保证）；若 getenforce=Enforcing 说明 boot 补丁被覆盖（如被 OTA 刷回），需重刷 boot_patched.img。

### 3.4 core_pattern / slots 被重置（内核态归零，重启后正常现象）
```
gpu_arb_write 1f2b790 ffffffc0013e4400     # slots ← memcpy
kfunc246 str ffffffc001f613c8 '|/data/local/tmp/roothelper.sh'
```
（rootify.sh 在开机钩子里自动做这两件事；确认方式：`kfunc246 show ffffffc001f613c8 36` 应看到 `7c2f646174612f6c6f63616c2f746d70...`）

### 3.5 想彻底回到出厂
1. dd 恢复 boot：`su -c 'dd if=boot_backup.img of=/dev/block/boot && sync'`（走 root_cmd 通道拿全 caps）
2. 恢复 install-recovery.sh：用 install-recovery.sh.orig 覆盖
3. 删除 /system/bin/rootify.sh、/system/xbin/su
4. 重启。/data 里的工具文件（/data/local/tmp/*）不影响系统，可留可删。

## 4. system_backup.img 的完整性问题（重要）

**首次 dd 流式传输被 adb 掉线打断（735MB/1GB），后以 4×256MB 分块重拉。接手人请先校验**：
```bash
ls -la TV_ROOT_HANDOFF/images/system_backup.img   # 必须 = 1073741824 字节
```
- 若缺失/大小不符：设备 root 仍在，重跑（分块方式见 02 文档 §6.2 前的 dd 命令，或 docs/03 坑 #E2 的 2>/dev/null 版本）；
- 校验内容正确性：镜像偏移 0x34800 附近应能看到 ext4 超级块/目录项（或用 7-Zip 直接打开 ext4 验证）。

## 5. 已知残留瑕疵（不影响使用）

- `boot_root.log` 由 rootify 以 root 写入、权限 600，adb shell 读不了（可用 kfunc show 或 root_cmd 通道读）。
- su 无 DAC_OVERRIDE（bounding set 限制），全权操作必须走 roothelper——设计如此，不是 bug。
- 内核补丁使 `setenforce 1` 永久无效（返回成功但不生效）——这是预期行为。
