# 01 · 项目总览与结论

## 1. 背景与目标

用户有一台**小米电视 4A（设备代号 `matrix`，Amlogic S905L）**，诉求按优先级：

1. **root（首选）**——用户明确「我比较倾向于 root，你来调研和探索一下方案是否可行」。
2. **备选**：借鉴 Aerial 让电视开机进自定义精简桌面（`com.gathin.tvhome`，保留原厂桌面作恢复入口）。这条线在本项目里**只作为背景，没有推进**。

选中方案：[`Yeuoly/mitv4-utgard-lpe`](https://github.com/Yeuoly/mitv4-utgard-lpe) —— 利用 Amlogic 发布的 Utgard 内核驱动把物理地址校验 `mali_mem_validation_check()` 编译成 `return OK`，配合 Mali-400 PP 写回引擎，用 **132 字节的内核写入**把 `sys_call_table[244..259]`（16 个没人调用的 `sys_ni_syscall` 槽）改成任意内核函数地址，从而获得「内核函数调用 → 任意内核读写 → 关 SELinux → `core_pattern` 劫持 → uid=0」。

该 PoC 原本只在 **MiTV4（xmen，S905L2）** 上验证过，本项目的核心问题就是：**这台 4A（matrix）行不行？**

## 2. 结论（一句话）

> **方案在这台 4A 上成立，且最危险、最需要实机对齐的一步——任意物理写原语——已经在本机验证通过（128 字节精确写入）。**
> 距离 root 只差 **两个固件常量**（`kallsyms_lookup_name` 虚地址、`sys_call_table[244]` 物理地址），而取得这两个常量的两条现实路径（拿固件 boot.img / 自建 GPU 读原语）目前都堵着。

## 4. 当前唯一硬卡点

PoC 的 `run.sh` 需要（源码见 `mitv4-utgard-lpe-main/run.sh`）：

```sh
KLN_ADDR  = kallsyms_lookup_name 的虚地址        # 本机未知
SLOT_PHYS = sys_call_table[244] 的物理地址        # = sys_call_table + 0x7a0 - 0xffffffc000000000
```

- `/proc/kallsyms` 可读，但 `kptr_restrict` 把地址抹成 0（符号名+顺序可见，共 **91624** 行）。
- `dmesg` 可读且泄漏了 `.text/.data` **边界**（`0xffffffc001080000` / `0x1dde474` / `0x2029610`），但泄漏点都在内核后段，**无法反推早期 `.text` 里符号的确切地址**。
- 想拿常量只有两条路：**（A）拿到与本机同构建的内核镜像**（boot.img）离线解析；**（B）先用 GPU 造一个任意读**，再从内存里扫出来。两条都在推进中卡住，详见 [02](02-技术事实.md) 与 [05](05-路线与待办.md)。
