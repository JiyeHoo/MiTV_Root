## 3. 关键决策点

1. **不以「是否有 43 寸证据」为前提**：直接实机验证，用 `mali.ko` 的 28 字节函数拍板漏洞存在。
2. **先写后读**：写原语是 PoC 的核心引擎、且能在自有内存上安全自校准；读是新增能力，必须自建。
3. **按 dmesg 寄存器转储定位失败点**，而不是盲改代码——这条方法论救了后面的很多轮。
4. **读原语失败后没有换架构**：因为承载机制（job、WB、绑定）已全部验证，问题被精确定位到 shader 编码这一件事上。
5. **拒绝「盲写猜地址」**：错一次 = 一次 panic，候选空间 MB 级，风险收益比不可接受。
6. **固件路线不放弃**：因为它是唯一「30 分钟确定成功」的路径，且不消耗实机风险。
